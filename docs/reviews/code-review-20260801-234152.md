### DR-S1-01-未修复-高-缺失协议 code 的 200 JSON 被当成成功，可把畸形列表响应解释为空表
- **入口/函数**: `FeishuClient._request()`，随后进入 `list_records()`、`delete_record()` 或其他调用方
- **文件(行号)**: `src/feishu_client.py:193-218`
- **输入场景**: 飞书、网关或测试替身返回 HTTP 200 且 JSON 是对象，但缺少顶层 `code`，例如 `{}` 或 `{"data": {}}`。
- **实际分支**: `data.get('code', 0)` 把缺失的 `code` 默认成 0；`raise_for_status()` 通过；函数返回 `data.get('data', {})`。
- **预期行为**: 飞书响应信封缺少或包含非法 `code` 时应按畸形协议响应 fail closed，不能产生正常数据或成功确认。
- **实际行为**: `{}` 会被当成成功的空 data。`list_records()` 随后把缺失的 `items` 默认成空列表并返回“无记录”；`delete_record()` 会在 `_request()` 返回后直接返回 `True`。
- **直接证据**: 新实现第 204 行给缺失 `code` 默认 0，第 215 行仅在 `code != 0` 时抛错，第 218 行又给缺失 `data` 默认 `{}`。S1 新增测试只覆盖 non-JSON、显式错误码和 structured not-found，没有覆盖缺失 `code` 的 JSON object。
- **影响**: 读路径可能把协议故障误报为空表并驱动后续重复创建；删除等写路径可能返回未经协议确认的成功，破坏 fail-closed 和审计语义。
- **建议改法和验证点**: 要求响应必须显式含有可解析的 `code`；缺失或非法值抛 typed/protocol error。成功码还应要求 `data` 为对象。新增 `{}`、`{"data": {}}`、`{"code": null}` 和 `{"code": 0, "data": []}` 回归，证明 list/delete/write 均不会继续。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### DR-S1-02-未修复-中-存储序列化仍维护第二份字段类型表，注册表不能约束真实 wire conversion
- **入口/函数**: `FeishuStorage._to_feishu_fields()` 与 `_from_feishu_fields()`
- **文件(行号)**: `src/feishu_storage.py:244-301`; `src/feishu_storage.py:360-431`; `docs/gateflow/feishu-bitable-contract-repair/implementation-plan.md:214-217`
- **输入场景**: 注册表中的 Number 字段被增加、删除或改变类型，而存储层硬编码集合没有同步修改。
- **实际分支**: 写转换从函数内 `table_number_fields` 判断 Number；读转换又分别用 transactions/cash_flow/NAV/price_cache 的独立字段集合判断数值解析，完全不消费注册表且没有 coverage assertion。
- **预期行为**: S1 接受方案明确要求 repository/app 不得在没有 registry coverage assertion 的情况下定义第二份字段/类型列表；真实 wire conversion 至少应从 registry 导出 Number 字段，local-only price cache 可单独声明。
- **实际行为**: schema checker和 client 验证使用新注册表，但真正的 storage conversion 仍由旧列表决定；例如 transactions 读列表仍含 live/registry 均不存在的 `tax`，已证明两份定义可漂移。
- **直接证据**: 第 246-299 行重复声明五张远端表的 Number 字段；第 375-427 行再次独立声明读类型；注册表测试没有覆盖这些集合与 `TABLE_CONTRACTS` 的一致性。
- **影响**: schema check 可以通过而读写编码仍错误，形成“结构真源已统一”的假象；未来字段调整需要多点同步且容易静默错读/错写。
- **建议改法和验证点**: 提供 registry-owned numeric-field helper，远端表的读写转换统一消费它；只为 local-only `price_cache` 保留本地集合。增加逐表测试，确保所有 registered Number 字段按数值处理且 Text/Date/JSON/Select 不被误判。

- **严重程度（低/中/高/严重）**: 中

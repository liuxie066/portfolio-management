### DR-AGG-CF-01-未修复-中-FX共享校验函数没有显式绑定confirmation与record identity

- **入口/函数**: `CashFlowEventCompletionService._decide()` and
  `NavRecordService._assert_cash_flow_ready_for_write()` ->
  `evaluate_cash_flow_fx_confirmation()`
- **文件(行号)**: `src/app/cash_flow_fx_confirmation.py:18-45`
- **输入场景**: A caller supplies a structurally valid confirmation whose
  `source_hash`, date, rate, CNY amount, source, and evidence type match the
  fresh row, but whose stored `record_id` belongs to a different cash-flow row.
- **实际分支**: The helper never compares `confirmation.record_id` with
  `row.record_id`, so it returns `fx_confirmation_valid`.
- **预期行为**: The cash-flow-owned shared authority must independently reject
  cross-record evidence as stale with a structured `record_id` mismatch.
- **直接证据**: The comparison map contains only `source_hash` and
  `exchange_rate_date`; numeric and authority checks likewise omit record
  identity. The approved plan explicitly includes record identity in the exact
  confirmation match.
- **影响**: Current production callers query the local store by record ID, which
  reduces immediate exposure, but the supposedly central validator is not
  fail-closed on its public input contract. A future injected/imported caller or
  corrupted/mis-associated evidence row could authorize a foreign generated-
  field write or NAV gate incorrectly.
- **建议改法和验证点**: Add record ID to the exact comparison map and a
  negative regression using otherwise identical evidence from another record;
  retain passing NAV and valid-confirmation tests.
- **修复风险**: 低
- **严重程度**: 中

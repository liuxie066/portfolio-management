## Architecture Boundary Review

- Pure facts：CashFlowDatasetSnapshot 与 NormalizedValuationSnapshot 被放在无 Feishu/app 依赖的 contracts/models 层；repository 不导入 app service。
- Application orchestration：只有顶层 service 构建 run-scoped dataset 和 precheck；计算 service 只消费已验证对象。
- Repository：负责完整 raw projection、wire conversion、field-level mutation 和 fresh readback，不决定 asset_class 或 NAV 公式。
- Domain：负责 finite、枚举、业务键、经济敞口、现金流公式、NAV invariant 和 snapshot replay。
- External protocol：live schema/type、null clear、filter 和 batch behavior 由 S0/S7 evidence gate 约束，不从 fake client 结果外推。

未发现 plan 引入 repository → app 的反向依赖或让 cache 成为权威事实。

## Best-Practice and Optimal-Solution Review

- 方案复用现有 FeishuBatchWriteError、append-only compensation log、fresh read methods 和 finality details，不另建第二套恢复框架。
- 对危险 mutation 采用 plan-before-write、stage receipt、fresh readback 和 explicit overwrite authority，符合当前项目的 CAS/compensation 约定。
- 对 stock_value 选择兼容旧列名并修正内部语义，比立即 live schema rename 和历史全量迁移更小、更安全。
- 对 transactions 选择封锁 dormant writer，而不是为未启用产品面补做完整 ledger migration，避免范围膨胀。
- 对 schema_version 选择 reserved，而不是在本轮顺带实现迁移账本。

## Overengineering and Overcoupling Review

- CashFlowDatasetSnapshot 是解决 F06 内部 TOCTOU 的必要 run boundary，不是通用 data platform；字段范围被限定到 NAV/effect 所需证据。
- NormalizedValuationSnapshot 是解决 F10 的单一估值输入，不扩展为新的 pricing provider abstraction。
- S3、S5 已拆 A/B 子切片；S1-S6 禁止中途独立 release，避免 version skew。
- S2 与 S3A 可并行，但共享 converter/validator 必须依赖 S1，避免复制基础设施。

未发现缺乏当前 finding 支撑的新服务、通用框架或 live migration。

## Open Questions

1. 当前 live holdings_snapshot.as_of 到底是 Text 还是 Date？
   - 处理：S0 read-only metadata export 是 S1 前置 gate；与 canonical Text 不一致时停止并另立 migration。
2. Feishu Number 对 unit price 的实际 round-trip 精度能否维持逐行 replay？
   - 处理：S7 非生产 create/readback canary；不能满足时停止，不降低 assertion。
3. null 是否在当前 SDK/租户/field type 上稳定清空，batch delete 是否能返回足够的 confirmed stage facts？
   - 处理：official contract + request-map test + 单独授权的非生产 canary；无法区分 confirmed/unknown 时停止。
4. transactions 是否还有审计未发现的生产调用者？
   - 处理：S6 先做全仓与运行入口 inventory；发现调用者即停止 read-only 封锁实施并回报。
5. 外部人工编辑恰好发生在 fresh dataset/readback 与 NAV 写入之间时，是否要求跨表强一致？
   - 处理：当前 Feishu 无跨表事务，本方案记录 as-of fingerprint 并 fail closed 于可观察 mismatch；更强一致性需要另行 freeze/lease 设计。

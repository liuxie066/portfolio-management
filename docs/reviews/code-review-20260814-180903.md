### 1-未修复-高-dry-run 的 daily job 在 cash-flow gate 失败时仍会写入不可变估值证据

- **入口/函数**: `AccountNavRecorderService.record()` -> `except CashFlowDatasetRefusal` -> `NavValuationEvidenceStore.save()`
- **文件(行号)**: `src/app/account_nav_recorder_service.py:416-470`
- **输入场景**: 使用默认 dry-run 执行 `daily-job`，完成估值后命中可捕获的 cash-flow blocker。
- **实际分支**: 捕获条件只校验 writer、reason code 和证据完整性，没有校验 `dry_run=False` 与 `confirm=True`，因此调用 `save()` 创建 JSON 文件。
- **预期行为**: dry-run 不应写入任何运行时数据；只有已确认的正式 daily job 失败才应产生可重放的 `valuation_ref`。
- **实际行为**: 预览或监控调用会突破 dry-run 边界，持久化一个可用于后续正式重放的能力引用。
- **影响**: 破坏 CLI 和 repository 既有的 dry-run 无写入契约，并可能积累未经正式确认的证据文件。
- **建议改法和验证点**: 在共享捕获入口增加 `not dry_run and confirm` 守卫；增加回归测试，确认同一 blocker 在 dry-run 下不返回 `valuation_ref` 且不产生 JSON 文件。

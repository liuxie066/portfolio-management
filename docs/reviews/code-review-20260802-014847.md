## Findings

### S4-CR-01 — 未修复 — 中 — migration diagram orders unit apply before the credentials that apply requires

- **入口/函数**: operator migration state -> `scripts/install.sh --apply` ->
  `apply_install()`
- **文件(行号)**: `docs/deploy-linux.md:282-286`;
  `scripts/install_linux.py:794-802`
- **输入场景**: An existing plaintext installation follows the documented
  migration state from top to bottom.
- **实际分支**: The diagram says to install credential-capable code/unit before
  provisioning the two encrypted credentials. The accepted installer contract
  invokes `verify_encrypted_credential_presence()` before writing any unit and
  therefore rejects that order.
- **预期行为**: Documentation must distinguish harmless checkout/venv
  preparation from system-asset apply, then provision both credentials before
  applying the credential-bearing units.
- **实际行为**: The prescribed first mutation cannot complete, so the operator
  is blocked before reaching the credential-provisioning step and may be tempted
  to bypass the fail-closed installer.
- **影响**: The primary production migration runbook is not executable as
  written and creates pressure to weaken the security gate.
- **建议改法和验证点**: Rewrite the state sequence as checkout/venv preparation
  without apply -> rotate/provision both encrypted credentials -> apply
  credential-capable config/env/units -> secure preflight. Add assertions that
  credential provisioning precedes the apply marker in the runbook.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### S4-CR-02 — 未修复 — 低 — Conversation permission text permits an unspecified broader substitute

- **入口/函数**: Feishu administrator follows the two-role permission table
- **文件(行号)**: `docs/deploy-linux.md:107-116`
- **输入场景**: An operator chooses permissions for the Conversation app.
- **实际分支**: The table requests `im:message:send_as_bot` but also allows an
  undefined “equivalent message send permission”. Feishu's send-message API
  lists broader permissions among its alternatives.
- **预期行为**: The product's least-privilege runbook should name the exact bot
  send permission used by this integration and stop if it is unavailable.
- **实际行为**: The wording authorizes an operator to grant a broader message
  permission without a documented need.
- **影响**: The two-app split is correct, but the Conversation app may receive
  unnecessary access.
- **建议改法和验证点**: Remove the equivalent-permission escape hatch and add a
  documentation assertion for the exact `im:message:send_as_bot` scope.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 低

## Findings

### 1-未修复-高-证据顶层 holdings digest 未与估值内部持仓来源绑定

- **入口/函数**: `NavValuationEvidenceStore.prepare()` and `_validate_artifact()`
- **文件(行号)**: `src/app/nav_valuation_evidence_service.py:65-133, 202-228`
- **输入场景**: 调用方传入当前 Holdings 的顶层 `holdings_digest`，同时传入由另一份 Holdings 生成的 official normalized valuation。
- **实际分支**: `prepare()` 分别校验顶层 digest 格式和 valuation 的 official/account 属性，但未校验 `valuation.holdings_provenance.normalized_holdings_digest == holdings_digest`；加载时也仅分别校验 artifact digest 和 valuation digest。
- **预期行为**: replay capability 必须把同一份持仓事实、估值结果和顶层摘要不可分割地绑定，任何内部/外部 Holdings digest 不一致都应拒绝。
- **实际行为**: replay 只把 fresh Holdings 与顶层 digest 比较，因此构造错误或历史准备器缺陷可让另一份持仓的估值通过 replay。
- **直接证据**: `holdings_digest` 写入 artifact 的 114 行；valuation canonical payload 写入 118 行；两者之间无相等断言；`_validate_artifact()` 也未比较二者。
- **影响**: 可能将不属于 replay 当日持仓快照的总资产写入正式 NAV，破坏该能力的核心数据完整性。
- **建议改法和验证点**: 在 prepare 和 load 两侧都校验 valuation provenance 中的 normalized Holdings digest 与顶层 digest 完全一致；增加 mismatch 回归测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### 2-未修复-高-无效 valuation_ref 在具有副作用的 Holdings 预检之后才被拒绝

- **入口/函数**: `DailyNavJobService.run()` -> `_precheck_account()` -> `scan_global_orphans()` -> account recorder load
- **文件(行号)**: `src/app/daily_nav_job_service.py:24-82, 300-455`; `src/app/account_nav_recorder_service.py:115-160`
- **输入场景**: 显式 replay 请求携带空、格式错误、不存在或 account/date 跨作用域的 `valuation_ref`；或 `account="alice,bob"`。
- **实际分支**: 入口仅在 truthy `valuation_ref` 时做部分参数检查，未验证 reference 本身，也未要求 `normalize_accounts(account)` 恰为一个账户。随后 duplicate/existing-row 检查和 global Holdings preflight 已执行，最终到 account recorder 才加载并拒绝 evidence。
- **预期行为**: `valuation_ref` 是 replay capability；无效或跨作用域 capability 必须在任何会物化 Holdings 工作流的预检之前 fail closed，且只允许一个显式账户和一个显式日期。
- **实际行为**: 无效请求仍可先触发正式 Holdings preflight；逗号分隔账户也可进入多账户路径。空字符串则绕过 replay 的入口约束。
- **直接证据**: 322 行使用 `if valuation_ref`；323-329 行未调用 `normalize_accounts` 或 evidence store；366-455 行先执行账户解析、重复检查和 global preflight，evidence load 位于更下游的 account recorder。
- **影响**: 未授权或无效 replay 请求可在被拒绝前改变预检相关持久状态，同时违背 single-account replay 契约。
- **建议改法和验证点**: 入口使用 `valuation_ref is not None`，先解析唯一账户并用 expected account/date 加载证据，失败返回 `valuation_evidence_preflight`；将同一 store 注入下游 recorder。增加断言无效 ref 不触发任何 duplicate/global/account preflight 的测试。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

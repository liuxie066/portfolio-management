### DR-S3-RR-01-未修复-高-provider numeric parser 删除任意逗号，畸形值可被改写为有效数字

- **入口/函数**: `ProviderNumericFact.parse()` → `FutuPositionSnapshot.__post_init__()` → complete-slice validation
- **文件(行号)**: `src/domain/holdings.py:31-53`; `src/app/futu_balance_sync_service.py:73-108`
- **输入场景**: provider quantity 或 average_cost 为 `"1,2"`、`"10,,5"` 等非法 machine-number text。
- **实际分支**: parser 无条件执行 `.replace(",", "")`，将上述值分别改写为 `12` 和 `105`，然后标记 `VALID`。
- **预期行为**: authoritative provider 数值必须是原样可解析的有限数；adapter 不能修复或猜测数字格式。
- **实际行为**: malformed 与 valid 的状态边界被打破，且可将仓位/成本放大后写入。
- **直接证据**: line 42 在 `Decimal(...)` 之前删除全部逗号，未验证分组规则；Futu SDK 的 machine numeric 边界不需要 locale 修复。
- **影响**: 直接违反 F04 的 fail-closed 数值契约，存在错误数量/成本写入风险。
- **建议改法和验证点**: 移除逗号删除，直接对 trim 后原文做 `Decimal` 解析。增加 malformed comma quantity/cost 用例，断言 invalid 且零 diff/write。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### DR-S3-RR-02-未修复-中-falsy 非文本 currency 被折叠成 missing 而非 invalid

- **入口/函数**: `FutuOpenApiBalanceProvider._position_snapshot()` → `FutuPositionSnapshot.__post_init__()`
- **文件(行号)**: `src/app/futu_balance_sync_service.py:73-99,500-516`
- **输入场景**: provider currency field 存在但值为 numeric `0` 或 boolean `False`；目标是已有且 currency 有效的持仓。
- **实际分支**: 两层都使用 `str(value or "")`，把 `0/False` 折叠为 blank，进而标记 `currency_explicit=False`；existing-row 路径会把它当成“provider 未提供，保留人工值”。
- **预期行为**: `None`/blank/`N/A` 是 missing；已出现但类型/值不合法的 `0/False` 是 invalid，应阻断整个 source slice。
- **实际行为**: invalid provider fact 伪装成 missing，绕过完整切片 currency validation。
- **直接证据**: line 77 和 line 503 的 `value or ""` 丢失了值存在性/类型事实。
- **影响**: 不会当场错写 currency，但 source validity 证据会错误变成可信，违反三态契约。
- **建议改法和验证点**: 仅将 `None` 映射为 blank，其他原值按 `str(value)` 保留后由 `Currency` enum 判断。注入 `0/False`，断言 `currency_invalid`、零 fresh read/write。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### DR-S3-RR-03-未修复-高-缺失 market/position_side 被默认为 US/LONG

- **入口/函数**: `_market_from_code()` / `FutuPositionSnapshot` defaults → `_validate_authoritative_positions()`
- **文件(行号)**: `src/app/futu_balance_sync_service.py:55-68,500-516,1093-1146,1463-1468`
- **输入场景**: custom provider 未显式给出 position side，或 OpenAPI row 的 code 没有 market prefix 且 `position_market` 也缺失。
- **实际分支**: dataclass 将 side 默认为 `LONG`；`_market_from_code()` 将缺失 market 默认为 `US`。后续 validator 只能看到补齐后的“有效”值。
- **预期行为**: 缺失 side 保留为 unknown 并阻断；market 只能来自 code prefix 或 provider `position_market`，两者都缺失时保留 blank 并在 source-validation 阶段失败。
- **实际行为**: 缺失事实被运行时默认值伪装为权威 provider 事实，可建立错误的 US/LONG target。
- **直接证据**: line 66 的 `"LONG"` 默认与 line 1468 的 `else "US"` 在 source validator 之前已消除 missing state。
- **影响**: 直接破坏完整 authoritative slice 校验，并可将 unknown side 当成 long 自动写入。
- **建议改法和验证点**: position-side default 改为 `N/A`；`_market_from_code()` 不再猜 US。调整 quote-classification 预取以允许缺失 market 进入 source validator，并增加零 fresh-read/write 回归。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 高

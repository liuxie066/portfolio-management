## Findings

### DR-S3-01-未修复-高-provider currency 只校验三位字母，占位值可成为新持仓币种

- **入口/函数**: `FutuPositionSnapshot.__post_init__()` → `_validate_authoritative_positions()` → `_build_position_diff()`
- **文件(行号)**: `src/app/futu_balance_sync_service.py:72-106,1093-1136,1477-1484`
- **输入场景**: Futu 新持仓携带 `currency="NAN"` / `"BAD"` 等三位字母占位值，其他字段完整有效。
- **实际分支**: `currency_explicit=True` 且 `_valid_currency()` 只判断 ASCII、字母和长度 3，因而 source validation 通过；new-row diff 将该值作为 currency 写入。
- **预期行为**: 新行只能使用项目受支持的显式 provider currency；`CNH` 可规范化为 `CNY`，未知代码必须在任何 fresh holdings read/diff/write 之前失败。
- **实际行为**: 字段“形状”被当作“定义有效”，可污染 holdings currency 并使后续 FX/价值计算失去语义。
- **直接证据**: `_valid_currency("NAN")` 和 `_valid_currency("BAD")` 均返回 true；`_target_descriptor()` 会原样返回该 currency。
- **影响**: 违反 S3 “new rows require explicit valid provider currency”的核心写入边界，并可导致下游定价失败或错误折算。
- **建议改法和验证点**: 复用项目 `Currency` enum 作为受支持币种唯一真源，先将 `CNH` 规范化为 `CNY` 再校验。增加 `NAN`/`BAD`/`USDD` 失败注入，断言零 fresh diff read 和零写入。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### DR-S3-02-未修复-高-源中消失的旧持仓绕过 currency 校验后被清零

- **入口/函数**: `FutuBalanceSyncService._build_position_diff()` → `append_item(target=None)`
- **文件(行号)**: `src/app/futu_balance_sync_service.py:1244-1254,1270-1345`
- **输入场景**: fresh Feishu 切片有一个归属富途的旧 canonical stock，币种缺失或非法；完整 Futu source slice 中已无该持仓。
- **实际分支**: 只有 `target is not None` 分支检查 `current.currency`。对源中消失的行，`target=None` 分支直接 carry forward 非法 currency，并生成 quantity=0/avg_cost=null 的 replace target。
- **预期行为**: 任何现有行只能保留已验证有效的 currency；非法旧行应在 mutation 前失败并留给受控 repair workflow。
- **实际行为**: Futu sync 会修改一个它无权补全 currency 的非法行，同时保留非法值。
- **直接证据**: line 1305 的校验位于 `if target is not None` 内；line 1313 的 absent-target 分支无对应校验。
- **影响**: 违反“existing rows preserve valid currency”与 fail-closed 原则；历史异常行可被自动 workflow 继续变更。
- **建议改法和验证点**: 将 existing currency 校验提到 target 分支之前。增加 absent source + invalid existing currency 用例，断言失败、零 bulk write，并且有效旧行仍可显式清零。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### DR-S3-03-未修复-中-不支持的 stock market 到 diff 阶段才失败

- **入口/函数**: `_validate_authoritative_positions()` → `_build_position_diff()` → `_target_descriptor()`
- **文件(行号)**: `src/app/futu_balance_sync_service.py:1093-1141,1244-1254,1293-1304,1408-1438`
- **输入场景**: authoritative source 含 `security_type=STOCK, market=SG` 的完整有效行。
- **实际分支**: source validator 只检查 market 非空，然后 `_build_position_diff()` 先 fresh-read Feishu，直到 append target 时 `_target_descriptor()` 才报 unsupported market。production receipt 因而记为 `FUTU_POSITION_DIFF_INVALID` 而非 source validation failure。
- **预期行为**: 所有 provider-owned source facts 在 diff 开始前验证完成；不可表示的 market 应记为 source-validation failure，不读 holdings。
- **实际行为**: 一个确定的源契约错误依赖 Feishu fresh read 才能暴露，并且回执阶段错分类。
- **直接证据**: validator line 1135 只做 truthiness 检查；market-to-asset-type 的支持集只在 `_target_descriptor()` 中实施。
- **影响**: 破坏 S3 “complete authoritative slice before building any diff”与阶段化失败证据，并造成不必要的远程 holdings read。
- **建议改法和验证点**: source validator 对 eligible row 复用 `_target_descriptor()` 的 market/type 解析结果，将错误收集到 complete-slice validation。增加 unsupported STOCK market 回归，断言 `fresh_reads == 0` 且零写入。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

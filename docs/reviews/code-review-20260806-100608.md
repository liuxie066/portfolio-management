## Findings

### S2-DR-01-未修复-中-显式 user token 调用仍会先解析生产 Agent Secret

- **入口/函数**: isolated caller -> `FeishuClient(user_token=...)` -> `FeishuClient.__init__()`
- **文件(行号)**: `src/feishu_client.py:50-61`; `src/config.py:419-465`
- **输入场景**: 隔离测试/非默认调用方显式传入 `user_token`，同时进程启用 secure Feishu mode 但没有挂载 Agent credential（这是显式 token 调用不需要的凭据）。
- **实际分支**: constructor 在保存 `user_token` 前无条件执行 `config.get("feishu.agent.app_id")` 与 `config.get("feishu.agent.app_secret")`；secure resolver 对缺失 credential 抛 `missing_secure_credential`，请求头分支永远到不了显式 token。
- **预期行为**: 已接受计划保留“仅显式 constructor injection”的隔离 token 路径；显式 token 应独立于默认生产 Agent 配置，而默认无 token 客户端才必须绑定 Agent。
- **实际行为**: 显式注入在非 secure/恰好有 Agent 配置时表面通过，但在目标隔离场景仍被生产凭据解析耦合和阻断。
- **直接证据**: `self.app_id = app_id or config.get(...)` 和 `self.app_secret = app_secret or config.get(...)` 位于 `self.user_token = user_token` 之前且不受 token 分支控制；现有显式 token 测试运行于有本地 Agent 配置的环境，没有断言 Agent keys 未被读取。
- **影响**: 保留的显式测试/隔离调用契约在 secure 环境失效，调用方可能被迫挂载本不应拥有的 Agent Secret，扩大凭据暴露面。
- **建议改法和验证点**: 当 `user_token` 被显式提供时，仅保留显式 `app_id/app_secret` 参数值，不从 config 解析 Agent；当未提供 token 时继续默认解析 Agent。新增 secure mode + 空 credential directory 的测试，断言显式 token 构造成功、Agent keys 未读取、header 使用 token；同时保留默认客户端忽略配置型 user token 的回归。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

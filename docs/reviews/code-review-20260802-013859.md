## Findings

### S3-CR-01 — 未修复 — 中 — deployment and runtime duplicate the credential-name contract

- **入口/函数**: generated `LoadCredentialEncrypted` directives -> runtime
  `read_systemd_credential()` lookup
- **文件(行号)**: `scripts/install_linux.py:49-55`;
  `src/configuration/feishu_credentials.py:12-17`
- **输入场景**: A later change renames either role's runtime credential while
  updating only the resolver or only the installer.
- **实际分支**: The installer owns a second hard-coded copy of both names. No
  production code import or test binds those copies to the runtime constants.
- **预期行为**: Unit rendering, metadata preflight, and runtime resolution must
  consume one authoritative credential-name contract.
- **实际行为**: Both copies happen to match today, but the contract can drift
  silently while installer tests remain green. Secure mode would then load one
  filename and look up another.
- **影响**: Every affected service fails closed after deployment despite valid
  encrypted credentials; the failure spans Base jobs, event listener, and/or
  conversation receipts depending on which role drifts.
- **建议改法和验证点**: Import the S1 credential-name constants into the
  installer using a direct-script-safe repository path bootstrap, and add a
  direct `python scripts/install_linux.py --help`/import regression so the
  deployment entrypoint remains usable outside repository-root cwd.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

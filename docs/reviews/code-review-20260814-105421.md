### DR-S2-01-未修复-高-任何模块的 failure 字典都会被误报为 Cash Flow 校验失败
- **入口/函数**: `NavHistoryReceiptService._item_row()` ->
  `_cash_flow_failure_row()`
- **文件(行号)**: `src/app/nav_history_receipt_service.py:336-358`；现有非
  cash-flow producer 见 `src/app/daily_nav_job_service.py:230-244,272-286`
- **输入场景**: daily job 的 account run、duplicate audit 或 existing-row check
  抛出普通异常；job 已按现有 contract 写入 `failure={stage,
  exception_type,message}`。
- **实际分支**: `_item_row()` 对每个失败 item 无条件调用 cash-flow formatter；
  formatter 只判断 `failure` 是 dict。由于普通 failure 没有
  `code=CASH_FLOW_DATASET_BLOCKED`，它进入“Cash Flow 数据校验未通过”分支。
- **预期行为**: 只有 `CASH_FLOW_*` typed refusal contract 由 cash-flow formatter
  接管；其他现有 failure 仍显示原 status/stage/error。
- **实际行为**: duplicate audit、NAV 检查、估值或其他 account exception 被错误
  标成 Cash Flow 问题，原 stage 和错误描述消失，处理方向错误。
- **直接证据**: `:350-358` 对任意 dict failure 都返回非空行；daily job 在
  `:239-243` 和 `:281-285` 写的是无 `code` 的通用 failure 字典。
- **影响**: 本改动扩大到所有结构化失败并改变既有回执语义，用户会排查错误系统。
- **建议改法和验证点**: cash-flow formatter 首先要求 code 以
  `CASH_FLOW_` 开头，否则返回 `None` 交还 legacy path；新增带 stage 的通用
  failure 回归测试，断言原 stage/error 完整保留。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### DR-S2-02-未修复-中-effect infrastructure blocker 被错误指示为修改 Cash Flow 表
- **入口/函数**: `NavHistoryReceiptService._cash_flow_failure_row()`
- **文件(行号)**: `src/app/nav_history_receipt_service.py:359-384`；blocker 生产见
  `src/app/cash_flow_summary_service.py:209-268`
- **输入场景**: effect gate 调用失败、缺少 revision 或 dataset/effect
  fingerprint 不一致，产生 `EFFECT_GATE_FAILED`、`EFFECT_REVISION_MISSING`
  或 `EFFECT_SOURCE_FINGERPRINT_MISMATCH`，但没有可展开的 nested effect
  blockers。
- **实际分支**: formatter 因 `effect_blockers` 为空，把第一个 blocker 当成
  cash-flow row validation，输出“修正 Cash Flow 表”。
- **预期行为**: effect infrastructure/evidence failure 应给出 Run-ID 排查和重试
  指引；只有真实 row/field blocker 才提示修改 Cash Flow 表。
- **实际行为**: 用户被要求修改本来没有问题的业务数据，无法修复 gate
  availability/revision mismatch。
- **直接证据**: summary service 在 `:215-231,245-268` 生成上述 EFFECT_* 原因；
  receipt 在 `:376-384` 不看 reason code，统一输出表格修改动作。
- **影响**: 用户可见处置建议错误，重复修改数据仍无法解除 NAV 阻断。
- **建议改法和验证点**: nested effects 为空且首个 reason code 以 `EFFECT_`
  开头时使用通用 Run-ID/gate 排查文案；增加 EFFECT_GATE_FAILED 渲染测试，
  禁止出现“修正 Cash Flow 表”。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### DR-S2-03-未修复-中-跨账户 correction 给旧账户展示了新账户的 broker 和金额
- **入口/函数**: `CashFlowEffectService.nav_gate()` blocker projection
- **文件(行号)**: `src/app/cash_flow_effect_service.py:1152-1204,2138-2167`
- **输入场景**: 一笔已 applied cash flow 从账户 A/broker A 更正到账户 B/broker
  B；pending correction 同时以 `-previous_amount` 影响 A、以
  `+current_amount` 影响 B，因此两账户都被 gate 阻断。
- **实际分支**: `_effect_accounts()` 正确把 previous/current accounts 都列入；
  但 `nav_gate(account=A)` 和 `nav_gate(account=B)` 都从 effect 顶层 current
  source 字段投影同一个 broker/currency/signed_amount。
- **预期行为**: 每个 account 的 receipt 应展示该 account 对应 operation 的
  broker/currency/delta；不能把 B 的入金事实显示给 A。
- **实际行为**: A 的回执显示 broker B 和正 current amount，实际 A 的待处理
  operation 是 broker A 的负 reversal。
- **直接证据**: `_cash_flow_operations()` 在 `:1173-1180` 明确生成 previous
  negative/current positive 两个 operation；`_effect_accounts()` 在
  `:1188-1204` 扩大 account scope；`:2155-2166` 却直接读取 item 顶层字段，
  未按请求 account 选择 operation。
- **影响**: 友好回执中的核心 broker/amount 事实会错误，可能导致 operator 在
  错账户或错误券商上判断是否已反映。
- **建议改法和验证点**: blocker projection 对 cash-flow effect 使用现有
  `_cash_flow_operations()`，按请求 account 产出安全 `operations` 列表；标量
  字段仅在唯一匹配 operation 时保留。Receipt 从 operations 展开首项并报告
  其余数量。增加 A/B correction 的 gate projection 测试。
- **修复风险（低/中/高）**: 中
- **严重程度（低/中/高/严重）**: 中

## Findings

### S1-CR-01-未修复-高-非法 secure-mode 值会静默关闭保护并回退到明文密钥
- **入口/函数**: `config.get(<canonical app_secret>)` ->
  `_resolve_canonical_secret()` -> `secure_feishu_credentials_required()`
- **文件(行号)**: `src/configuration/feishu_credentials.py:19,36-37`;
  `src/config.py:371-389`
- **输入场景**: production unit/operator intended to enable secure mode but sets
  `PM_REQUIRE_SECURE_FEISHU_CREDENTIALS=treu`, `enabled`, or any other malformed
  non-empty value; a legacy App Secret remains in YAML/environment during migration.
- **实际分支**: membership in `_TRUE_VALUES` returns `False` for every unknown
  string. `_resolve_canonical_secret()` therefore treats the process as
  non-secure and selects the first plaintext candidate.
- **预期行为**: a malformed security-control value must fail closed with a
  redacted configuration error; only explicit recognized false values or an
  absent variable may disable the requirement outside generated production units.
- **实际行为**: the typo silently disables the control and returns the plaintext
  App Secret to the caller.
- **直接证据**: line 37 is a bare `value in _TRUE_VALUES`; there is no false-set or
  invalid branch. Lines 378-389 select plaintext whenever that boolean is false.
- **影响**: a one-character deployment typo defeats the primary at-rest/runtime
  migration guarantee without a startup error or audit issue.
- **建议改法和验证点**: parse absent/empty as false, explicit true/false sets as
  their values, and raise redacted `invalid_secure_mode` for anything else.
  `inspect_config` and `validate_deploy_config` must convert it to a structured
  issue and never recover by reading plaintext. Add CLI/config tests for an
  invalid value with a real legacy fixture secret and assert non-zero/redaction.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### S1-CR-02-未修复-中-底层异常链保留 credential 路径或原始字节，破坏脱敏异常契约
- **入口/函数**: `read_systemd_credential()`
- **文件(行号)**: `src/configuration/feishu_credentials.py:52-57,65-68,69-80,88-91`
- **输入场景**: credential path permission/open/read failure，或 credential 含
  非 UTF-8 bytes；上层记录完整 traceback 或检查 exception cause/context。
- **实际分支**: code raises the redacted `FeishuCredentialConfigError` using
  `raise ... from exc`.
- **预期行为**: plan 和 docstring 均承诺 exception/output 不包含 credential
  path 或 bytes；outer error 应是唯一可观察异常事实。
- **实际行为**: exception chain retains the original `OSError` (including path)
  or `UnicodeDecodeError` (which retains the original bytes object). A normal
  traceback prints the cause, bypassing the redacted `__str__`.
- **直接证据**: lines 57, 68, 77, and 91 explicitly chain the original exception.
  Existing tests assert only outer `str(exc)` and do not format the traceback or
  cover invalid UTF-8.
- **影响**: diagnostics/logging can expose credential storage paths and portions
  or objects containing secret material precisely on malformed/error paths.
- **建议改法和验证点**: suppress the original exception in the raised diagnostic
  (`from None`) and ensure no caller serializes a cause. Add invalid-UTF-8 and
  open/read-failure tests that use `traceback.format_exc()` and assert neither the
  credential directory nor fixture bytes appear.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### S1-CR-03-未修复-中-show-secrets 仍会回显 App ID/open_id，违反已接受的隐私展示契约
- **入口/函数**: `pm config inspect --show-secrets` -> `inspect_config()`
- **文件(行号)**: `src/config.py:163-169,457-465,514-540`;
  `scripts/pm.py:1330-1340`
- **输入场景**: operator requests canonical Bitable/conversation App ID or
  conversation open_id together with `--show-secrets`.
- **实际分支**: `must_redact` is false because `NON_DISCLOSABLE_KEYS` contains only
  the App Secret keys. The raw identifier is returned even though all identifiers
  remain in `SECRET_KEYS` for normal inspection.
- **预期行为**: the accepted plan states App IDs/open_id remain redacted in
  operator-facing inspection for privacy; only non-sensitive unrelated keys may
  honor `--show-secrets`.
- **实际行为**: `--show-secrets` returns full personalized identifiers.
- **直接证据**: lines 163-169 omit every App ID/open_id from
  `NON_DISCLOSABLE_KEYS`; line 535 uses that set as the only permanent-redaction
  guard.
- **影响**: support transcripts or diagnostics can disclose user-specific Feishu
  identities even after App Secret output was correctly blocked.
- **建议改法和验证点**: add canonical and legacy App ID/open_id keys to the
  permanent non-disclosure set, or replace it with a role-identity privacy set.
  Extend the `--show-secrets` CLI test to assert all five canonical values remain
  redacted and the raw fixtures are absent.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

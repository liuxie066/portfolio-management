### S3-DR-01-未修复-中-安装器会读取并重写含旧 Secret shadow 的现有 EnvironmentFile

- **入口/函数**: `apply_install()` -> `Path.read_text()` -> `render_env_file()` -> `_write_text(..., overwrite=True)`
- **文件(行号)**: `scripts/install_linux.py:295-334, 896-988`
- **输入场景**: 升级主机的目标 EnvironmentFile 仍含 `FEISHU_*_APP_SECRET` 或 `OM_FEISHU_BOT_APP_SECRET` 明文 shadow。
- **实际分支**: apply 将整个文件读入字符串，再以 `overwrite=True` 重写原路径；即使内容字节不变，安装器仍接收并复制了 Secret。
- **预期行为**: 已有 env 只扫描 key 名作迁移证据并原样保留；仅当文件不存在时才生成无 Secret 默认文件。
- **实际行为**: 违反已接受的“安装器不接收、复制 Secret”不变量，且无必要地对敏感配置执行写入。
- **直接证据**: `existing_env = paths.env_file.read_text(...)` 保留全文；`render_env_file(... existing_content=existing_env)` 返回全文；后续 `_write_text(... overwrite=True)` 写回。
- **影响**: Secret 处理边界被安装器扩大，审计声明与实际数据流不一致。
- **建议改法和验证点**: apply 不读取现有 env 全文，写入使用 `overwrite=False`；新增原样保留回归和 canonical 非秘密 env 映射测试。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### S3-DR-02-未修复-中-flow-style YAML 可绕过 plaintext Secret key 扫描

- **入口/函数**: `verify_feishu_role_mapping()` -> `_yaml_secret_key_presence()` -> `yaml.safe_load()`
- **文件(行号)**: `scripts/install_linux.py:276-375`
- **输入场景**: config 使用 `feishu: {agent: {app_secret: value}}` 一行 flow-style YAML。
- **实际分支**: 扫描器只比较每行第一个冒号前的 key，看到的是 `feishu`，随后 `yaml.safe_load()` 将 `app_secret` 值加载进内存。
- **预期行为**: block-style、quoted-key 和 flow-style `app_secret` 都在 YAML 解析前按 key 名 fail closed，错误不回显值。
- **实际行为**: 合法 YAML 形式可让安装器读取本应只报 key 名的 Secret。
- **直接证据**: 旧扫描逻辑是 `stripped.split(":", 1)[0] == "app_secret"`，没有覆盖内嵌 mapping。
- **影响**: 安装器的明文 Secret 阻断可被配置表示法绕过，安全不变量不完整。
- **建议改法和验证点**: 在解析前检测 block/quoted/flow-style `app_secret` key token；增加 flow-style 回归，断言只出现 redacted key 错误。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

### S3-DR-03-未修复-高-`--apply --enable-*` 可跳过 secure preflight 直接激活消费者

- **入口/函数**: `apply_install()` -> generated unit writes -> `systemctl enable --now`
- **文件(行号)**: `scripts/install_linux.py:1093-1124`; `scripts/install.sh:213-229`
- **输入场景**: 操作者按公开 CLI 使用 `--apply --enable-timer`、`--enable-api-service`、`--enable-quality-timer` 或 `--enable-holdings-event-listener`，credential 文件存在但内容无效，或 config 仍含 secure doctor 会阻断的 user-token override。
- **实际分支**: 安装器只执行 `daemon-reload`，然后直接 `enable --now`；生成的 `portfolio-feishu-preflight.service` 没有被运行。
- **预期行为**: 任何激活请求必须在新 unit 装入后先运行本地 secure preflight；任一失败都必须在第一个 `enable --now` 之前停止。
- **实际行为**: 元数据存在性检查被当成了可运行凭据和完整配置的代替，与文档中“preflight 后才启用”矛盾。
- **直接证据**: `systemd_commands` 只包含 `daemon-reload` 和各个 `enable --now`，无 `systemctl start portfolio-feishu-preflight.service`。
- **影响**: persistent timer 可因补跑立即触发，API/listener 会立即启动；错误身份或无效 Secret 可在业务进程中才暴露，导致已知可避免的生产失败。
- **建议改法和验证点**: 当任意 enable flag 存在时，将 oneshot preflight 强制插入 `daemon-reload` 与所有 activation 之间；新增 preflight 失败时无 activation 命令的回归。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

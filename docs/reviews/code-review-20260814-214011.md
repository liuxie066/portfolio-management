## Findings

### DR-AGG-01-未修复-高-重建记录只校验自洽 identity，未强制每条 Holdings row 属于目标账户

- **入口/函数**: `HistoricalNavValuationEvidenceService._load_receipt_holdings()` → `ValidatedHoldingsSnapshot.from_public_validation()`
- **文件(行号)**: `src/app/holdings_nav_preflight_service.py:342-377`
- **输入场景**: durable receipt 的 item/provenance account 是 `lx`，但 serialized records 中存在一条 account=`sy` 的完整、自洽且 digest-valid row；operator expected digest 来自同一 receipt。
- **实际分支**: identity loop 只比较 `identity.account` 与 row field `account`，两者同为 `sy` 即通过；当前 pure validator 只要求 account 存在，不要求它等于恢复目标；`from_evaluation(account="lx")` 也未显式拒绝 row account `sy`。
- **预期行为**: exact-account historical recovery 必须要求 every reconstructed row account == requested account before valuation or artifact creation.
- **实际行为**: mis-scoped row can reach typed snapshot/valuation preparation; later digest checks prove dataset identity but do not prove account isolation because expected digest may originate from the same malformed receipt.
- **直接证据**: the only target-account checks are receipt item/provenance checks and identity self-consistency; no condition compares `fields["account"]` with the method `account` argument.
- **影响**: malformed or corrupted historical receipt may mix another account's holdings into a final `lx` NAV artifact, violating account isolation.
- **建议改法和验证点**: reject any reconstructed row whose normalized account text differs from the requested account before record digest/validation; add a regression that rehashes a syntactically valid cross-account row and updates receipt provenance/expected digest as needed, proving scope rejection is independent of digest self-consistency.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

## Findings

### 1-未修复-高-effect revision 没有绑定 dataset 指纹，另一份 source 的成功 gate 也可授权当前 NAV

- **入口/函数**: `CashFlowSummaryService.build_dataset()` → `CashFlowEffectService.nav_gate()` → `CashFlowDatasetSnapshot.assert_official_scope()`
- **文件(行号)**: `src/app/cash_flow_summary_service.py:206-255`; `src/app/cash_flow_effect_service.py:2025-2065`; `src/domain/cash_flow_contracts.py:918-928`
- **输入场景**: effect service 因 stale adapter、错误 store scope 或测试替身返回了另一次 scan 的 `effect_store_revision`/success，但该 scan 对应的 cash-flow source 不是当前 `preliminary.financial_fingerprint`。
- **实际分支**: builder 只要看到非空 revision 且 `success=True` 就接受 gate；写入前只比较 gate 内 revision 和 snapshot 字段是否相等，不比较 gate 所扫描的 source fingerprint/source digest。
- **预期行为**: effect gate 必须回传并绑定它实际消费的 dataset financial fingerprint；builder 和 official assertion 都要拒绝缺失或不匹配的 source binding。
- **实际行为**: 一个内部自洽但对应其他 source 的 revision 可以让 dataset `complete=True`，并被持久化到 NAV details。
- **直接证据**: `nav_gate()` 返回 account/date/revision/blockers，但不返回 dataset fingerprint；`build_dataset()` 第 231-250 行只检查 revision/success；`assert_official_scope()` 第 918-928 行也只检查 revision/account/date。已有 mismatch 测试仅篡改 snapshot revision，没有覆盖“revision 与 gate 内部相等但 source 不同”。
- **建议改法和验证点**: `nav_gate()` 在 dataset 路径返回版本化 `cash_flow_financial_fingerprint`；builder 对缺失/不匹配添加 blocker，snapshot assertion 再次比对。新增 stale gate 故障注入：revision 非空、success=true、account/date 正确但 fingerprint 属于另一 source，确认零 NAV 写入。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### 2-未修复-中-frozen dataset 仍持有可变的嵌套 raw_fields，assert 与计算之间可发生事实漂移

- **入口/函数**: `RawCashFlowRecord.__post_init__()` → `CashFlowDatasetSnapshot.raw_rows`
- **文件(行号)**: `src/domain/cash_flow_contracts.py:87-105`; `src/domain/cash_flow_contracts.py:712-782`
- **输入场景**: raw field 含 list/dict 输运值或额外投影字段；构造 dataset 后，原输入或从 `canonical_fields()` 取得的嵌套对象被原地修改。
- **实际分支**: `RawCashFlowRecord` 仅用 `MappingProxyType` 冻结顶层 mapping，嵌套 list/dict 仍是同一可变引用；`CashFlowDatasetSnapshot` 只把 raw row 放进 tuple。
- **预期行为**: 被声明为 frozen 的运行事实集应深度冻结 raw field 值，使 fingerprint、blocker 和完成行在整个 run 中不可改变。
- **实际行为**: 在 official assertion 前变更会造成拒绝服务；若在 assertion 与 details/summary 消费间发生并发变更，则 persisted fingerprint 与实际 raw object 不再一致。
- **直接证据**: 第 101 行的 mapping value 原样保留；同文件已有 `_freeze_value()`/`_freeze_mapping()` 可深度冻结 blocker、FX identity 和 gate，但 raw row 未复用。
- **建议改法和验证点**: `RawCashFlowRecord` 复用深度 freeze helper，并确保 `canonical_fields()` 不泄漏可变内部引用。新增 nested extra field 测试，原输入修改不影响 full fingerprint，从 row 取得的嵌套容器也不可原地更改。
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

## Findings

### DR-S7-RR-01-未修复-高-完整 NAV builder 仍会制造缺失 account 并接受跨账户/无 record_id 行

- **入口/函数**: `_build_nav_index_payload()` / `_build_nav_payload_from_cache_rows()` -> `preload_nav_index()` / versioned disk replay -> write existence decision
- **文件(行号)**: `src/feishu/repositories/nav_history_repository.py:86-127,166-211,384-408,790-812`
- **输入场景**: account-scoped remote row or versioned cache row has a missing account, an account different from the requested scope, or a missing `record_id`.
- **实际分支**: both builders fill a missing account from the caller scope, accept a mismatched account unchanged, and allow `record_id=None`. The resulting row is published under the requested account. The write planner keys only by date and treats a row without record ID as a create target.
- **预期行为**: account and record identity are observed source facts. A complete canonical read must require a non-empty record ID and non-empty account, and an account-scoped read must reject a scope mismatch; it must never manufacture either identity fact.
- **实际行为**: a damaged cache can serve another account's NAV through the requested account, while a malformed remote row can be converted into an apparently valid row or cause a duplicate create on a later write.
- **直接证据**: lines 102-103 and 181-182 explicitly assign the requested account only when the source field is absent; neither builder validates the non-empty record ID captured at lines 97/173 nor checks account equality. `_write_nav_full_records()` treats a matching date with a falsey record ID as create.
- **影响**: the public cache can cross account boundaries, and a write can duplicate an existing canonical date when source record identity is absent. This violates the S7 lossless-read and safe write-before-read contract.
- **建议改法和验证点**: add one shared identity validator used before model reconstruction; require source account and record ID, require scoped-account equality, and wrap every violation in `NavHistoryReadIntegrityError`. Add remote/cache missing-account, mismatched-account, and missing-record-ID regressions, including a write assertion that no mutation request is sent.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 高

### DR-S7-RR-02-未修复-中-全局 duplicate audit 绕过 canonical builder，仍会对无效行报告成功

- **入口/函数**: `audit_nav_history_duplicates(account=None)` -> `_nav_duplicate_groups_from_rows()`
- **文件(行号)**: `src/feishu/repositories/nav_history_repository.py:215-260,285-323`
- **输入场景**: unscoped/global duplicate audit receives a row with missing/invalid date, missing account, or malformed canonical identity.
- **实际分支**: `_nav_duplicate_groups_from_rows()` silently skips rows without a parseable account/date. The new canonical builder validation runs only inside `if account`, so the global path returns `success=True` and counts the raw row while omitting it from duplicate groups.
- **预期行为**: scoped and global audit must share the same canonical identity validation; an invalid source row must block the audit rather than produce a false green result.
- **实际行为**: the scoped regression passes, but the operational global audit still hides invalid rows.
- **直接证据**: builder invocation and fail-closed cache handling are guarded by `if account` at lines 309-315. The duplicate grouper converts an invalid string date to `None` and continues when account/date is falsey.
- **影响**: an operator can receive a successful global duplicate audit even though its input is structurally incomplete, weakening the audit gate used before repair or investigation.
- **建议改法和验证点**: validate every global row through the same complete canonical builder before calculating duplicate groups, without publishing a cross-account cache. Add global invalid-date/account/record-ID tests asserting no success result.
- **修复风险（低/中/高）**: 低
- **严重程度（低/中/高/严重）**: 中

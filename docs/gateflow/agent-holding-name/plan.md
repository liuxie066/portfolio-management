## Evidence and smallest design
Current HTTP holdings endpoints lack exact-record actions and rely on loopback only; quality token is read-only and must not be repurposed. Existing reconciliation supports explicit HK name lookup; process_event_notification mutates immediately and queues terminal receipts. Generic apply_missing does not enable name evidence and may write other missing fields. Therefore reuse underlying protected workflow through a new narrow public name-only method, not either broad entry. Existing _execute_patch owns cases, attempt-before-write, digest-protected patch and readback; _locked owns record/account lock. Avoid parallel direct Feishu/DB repair code.

One behavior slice: default-disabled authenticated preview/execute/status with durable single-use operation and reused name-only mutation.

## Authentication and authorization
Use trusted server config agent_operations.enabled (strict true) and agent_operations.principals list. Each principal has unique id, token_sha256 (64 hex), explicit grants list of exact record_id/account/broker triples. No wildcard, blank, duplicate-token or ambiguous principal configuration permitted; malformed configuration fails closed. Only capability is complete_name. Do not generate credentials or add actual principal values to config. Example docs use placeholders only. Tokens accepted only Bearer header, compared constant-time after SHA256; never log/store/return bearer or token hash. Reject absent config/disabled before constructing the new Agent operation service/state or accessing any row/provider. Existing create_app PortfolioService bootstrap remains unchanged; no unrelated app-lifecycle rewrite. Do not reuse quality.read_token or user-controlled principal headers. All three endpoints re-authenticate and reauthorize exact grant; confirmation additionally verifies live row account/broker still match. Grant removal/principal config change invalidates access; bind preview to a canonical grant identity/version digest including principal id and exact grant (no secrets). Existing loopback restriction stays; no network settings change.

## API and state contracts
POST /api/v1/agent/holdings/{record_id}/name-preview (empty strict body), POST .../name-confirm (strict {preview_id}), GET .../name-operations/{preview_id}. Record path constrained ASCII safe ID, max128; nonce random uuid4 hex only. Forbid unknown body keys/actions/URLs/fields/notify parameters. No arbitrary handler dispatch. Separate router/module allowed to keep http.py integration small. Errors generic structured status: auth401, scope403, disabled503, stale/expired409, no-data404, provider unavailable/manual nonwrite result. Never include raw exceptions, amounts or entire validation payload. Auth before row lookup and operation lookup; mismatch gives generic rejection without leaking other record existence.

Preview fresh-reads only exact record and validates only eligible explicitly typed non-Futu hk_stock empty name with exact evidence (initial scope HK only, reuse verified_hk_name). Reject out-of-grant identity before provider calls. Existing name -> no-op preview, no write on confirm. Unknown/malformed identity/evidence/timeout -> not executable. Return current name/currency, proposed name, source/code/market/retrieved_at and blockers limited to field/status/reason (not current amounts). No Feishu write, case materialization or receipt in preview. It MAY persist a local operation snapshot explicitly documented; this is not a fully side-effect-free endpoint. Pure recheck result no-action can omit operation token. Eligible preview returns random preview_id, expiry default300s server UTC; no client TTL. Store only principal id, grant digest, exact record id/identity, full canonical record digest, proposed name, safe evidence and timestamps; never store raw full record or money/quantity. Nonce is not authorization by itself.

Use small new operation-state mixin/table in existing OperationStateStore (additive schema, no new daemon/database). Atomic previewed -> executing transition before any external write; operation states previewed/executing/succeeded/noop/rejected/unknown. Bind idempotency to preview_id+principal+record+action; no second independent idempotency framework. Durable replay of terminal results returns same sanitized result and never writes. Concurrent same operation only one claim. Different operations on same record serialize on existing record/account locks; second cannot overwrite newly filled name. A crash while executing remains conservative unknown/in-progress and never automatically reissues; status reports attention required, no hidden retry. Store final safe outcome. Scope mismatch/expiry rejected before claim; stale source/changed proposed evidence after claim terminal rejected (no write). GET status uses read-only operation retrieval after auth; no provider requests or write/recovery. No cleanup daemon; local retention and future expiry pruning documented as maintainer follow-up.

Confirmation performs normal grant checks, atomically claims operation, then invokes narrow workflow method with expected record digest/proposed name/grant identity and principal id. Under existing lock fresh-read, verify exact identity and digest, ensure name still empty, re-query matching HK evidence, compare exact proposed name/source/code/market (not equal retrieval timestamp). If another process already filled name, return safe stale/no-op without overwrite. Recheck current row before normal protected patch; if currency/other field changed vs preview reject rather than modifying it. Do not require currency to be HKD or write currency; return existing currency blockers. Unknown workflow cases suppress another name write, including across preview ids. No bypass of durable applying/unknown states.

Workflow public method delegates _execute_patch with only asset_name as mutation target and the FULL fresh same-record observed case set. Execute may materialize same-record validation cases (including currency blockers) but never writes those fields; preview never materializes cases. This is necessary because existing materialize_and_prepare resolves absent case keys; a name-only observed set would incorrectly close other blockers. Add explicit enqueue_receipts=False option to _execute_patch, default True for old callers; propagate it through materialize_and_prepare_holding_apply into both discovery materialization and absent-case closure, then terminal/attention finalization; ensure ALL discovery/terminal/attention receipt paths respect it and default old event behavior is unchanged. New Agent path cannot request notifications at all. After fresh readback, resolve obsolete same-record cases through existing workflow proof with enqueue_receipts=False; no other row/account materialization and no NAV recomputation. Don't close cases merely from mutation return; use authoritative postwrite fresh evaluation. Persist existing apply audit with principal/operation id, no secrets. If exception after remote attempt, return unknown and do not retry. Sanitized operation error auditing (stable codes, not raw payloads).
